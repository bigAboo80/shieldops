# ShieldOps

[English](README.md) · **Русский**

Сканер безопасности Kubernetes без агентов. Находит опасные сочетания прав, секреты в открытых наружу приложениях, уязвимости образов и пути атаки, делает HTML-отчёт и показывает, что изменилось с прошлого скана.

В этом репозитории открытая часть: консольная команда `scan`, граф, детекторы и HTML-отчёт. Образ и Helm-чарт запускают ShieldOps внутри вашего кластера с веб-интерфейсом — бесплатно для одного кластера.

Без агентов. Без облака. Данные не покидают ваш кластер.

## Установка в кластер (10 минут)

```bash
helm install shieldops oci://ghcr.io/bigaboo80/charts/shieldops -n shieldops --create-namespace
```

Первые результаты появляются через несколько секунд, уязвимости образов — через 1–3 минуты. После установки выводится, как получить пароль администратора и открыть веб-интерфейс (`kubectl port-forward`, по умолчанию в сеть ничего не открыто).

Главная страница — **«Исправьте на этой неделе»**: до пяти действий по вашим приложениям с готовым патчем или скриптом исправления. Компоненты Kubernetes вынесены на отдельную вкладку.

**Бесплатный тариф**, без лицензии:
- один кластер;
- все проверки и пути атаки;
- главная страница;
- решения по находкам (принятый риск, ложное срабатывание);
- патчи и скрипты исправления.

**Pro**, по лицензии:
- уведомления и сводки (Telegram, Mattermost);
- сроки исправления (SLA);
- Merge Request с исправлениями в ваш GitOps-репозиторий;
- пользователи и роли, SSO;
- подписанные отчёты и PDF;
- меры ФСТЭК и отчёт за период.

Истёкшая лицензия никогда не останавливает сканирование и не удаляет данные.

## Что находит

- **Учётные записи с cluster-admin** в работающих приложениях.
- **Секреты в открытых наружу приложениях** — тома, projected-тома, `envFrom`, `env` при доступе через LoadBalancer/NodePort.
- **Открытые наружу приложения с известными CVE** уровня CRITICAL/HIGH.
- **Пути атаки** — кратчайшие пути из интернета (Service LoadBalancer/NodePort, Ingress) через приложения, токены их ServiceAccount и действующие права RBAC до Secret, узлов и повышения прав. Оценка риска 0–100 объясняется весами; путь нарисован схемой в начале отчёта.

Находки — по workload (`Deployment/web`, `StatefulSet/db`, …), а не по подам: три реплики дают одну находку, и находка узнаётся после перезапусков и выкаток.

## Как работает

```
Kubernetes API (только чтение) → инвентаризация → граф в SQLite → детекторы → отчёт
```

ShieldOps читает кластер через Kubernetes API и строит граф связей между подами, учётными записями, ролями, сервисами и секретами. По этому графу он ищет опасные сочетания.

ShieldOps никогда не читает Secret — даже метаданные. RBAC не умеет выдать право «только метаданные», и токен, который может перечислять Secret, мог бы прочитать их значения. Какие секреты использует под, видно из его описания.

Каждый скан хранится в локальной базе SQLite, поэтому отчёт показывает **новые** и **исправленные** находки с прошлого успешного скана. Скан без Trivy не объявляет CVE-находки исправленными.

CVE ищет [Trivy](https://github.com/aquasecurity/trivy) по всем образам контейнеров и init-контейнеров. Каждый образ сканируется один раз.

## Запуск со своей машины (CLI)

```bash
# учётная запись сканера только на чтение (один раз на кластер)
kubectl apply -f deploy/rbac.yaml
# короткоживущий токен для неё
kubectl -n shieldops create token shieldops-scanner --duration=1h

make build
./bin/shieldops scan -kubeconfig ~/.kube/config -output report.html
```

| Флаг | По умолчанию | Значение |
|---|---|---|
| `-kubeconfig` | `$KUBECONFIG` или `~/.kube/config` | путь к kubeconfig |
| `-context` | текущий | контекст kubeconfig |
| `-namespace` | все | namespace для скана |
| `-exclude-namespaces` | нет | namespace через запятую, которые пропустить |
| `-platform-namespaces` | нет | дополнительные namespace компонентов кластера |
| `-db` | `shieldops.db` | путь к базе SQLite |
| `-output` | нет | путь HTML-отчёта |
| `-lang` | `ru` | язык отчёта: `ru` или `en` |
| `-timezone` | `Europe/Moscow` | часовой пояс отчёта |
| `-fstek` | нет | таблица мер ФСТЭК: `117` или `17` |
| `-skip-trivy` | `false` | не искать CVE |
| `-trivy-cmd` | `trivy` | команда trivy |
| `-trivy-timeout` | `20m` | время на скан образов |
| `-sign-key-file` | нет | подписать отчёт |

Для поиска CVE нужен Trivy в `PATH`. Сервер базы данных не нужен.

## Отчёт

Один самодостаточный HTML-файл без скриптов и внешних ресурсов. В нём:
- резюме;
- пути атаки со схемами;
- находки приложений по критичности;
- отдельный раздел платформы кластера;
- исправленные с прошлого скана;
- с `-fstek` — меры ФСТЭК.

Печать на A4.

### Подписанные отчёты и `shieldops verify`

```bash
shieldops keygen -out keys
shieldops scan -sign-key-file keys/shieldops-signing.key -output report.html
shieldops verify -pub keys/shieldops-signing.pub report.html
```

Подпись Ed25519 отсоединённая: файл `.sig` лежит рядом с отчётом. Аудитору отдаётся только `.pub`. Это не квалифицированная электронная подпись.

## Архитектура

```
cmd/shieldops/   CLI: scan, keygen, verify
internal/
  connector/     клиент Kubernetes API
  inventory/     сбор объектов
  graph/         граф в SQLite
  paths/         пути атаки, оценка риска
  detectors/     детекторы, сравнение сканов
  report/        HTML-отчёт
  signing/       подписи отчётов
pkg/trivy/       поиск CVE через Trivy
```

## Разработка

```bash
make build
make test
```

Сквозная проверка: `test/e2e/fixtures.yaml` создаёт намеренно уязвимый namespace. Удаление: `kubectl delete -f test/e2e/fixtures.yaml`.

## Полный продукт

Образ запускает полный продукт:
- сканы по расписанию;
- веб-интерфейс;
- разбор находок, переживающий пересканирование;
- журнал аудита;
- Helm-чарт.

Лицензия включает функции Pro. Работает в закрытых контурах: скопируйте образ в свой registry и укажите `image.repository`.
